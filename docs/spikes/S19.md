# S19 ConstitutiveModelsApplication 및 초탄성 재료 모델

- 질문: `KratosMultiphysics.ConstitutiveModelsApplication`의 재료 모델(Mooney-Rivlin, Yeoh, Ogden, 비압축 Neo-Hookean 등)이 적분점 기하(`NurbsVolume` + `CreateQuadraturePointGeometries`) 위 SM `TotalLagrangianElement3D*` / `UpdatedLagrangianElement3D*`에서 동작하는가?
- 결과: **`ConstitutiveModelsApplication`은 아니오(실패); 대안인 `ConstitutiveLawsApplication.HyperElastic3DLaw`는 `UpdatedLagrangianElement3D4N`에서 예(기계 정밀도 일치)**
- 근거:
  - `pytest WHT_IGA/tests/kratos_spikes/test_s19_constitutive_models.py` 16/16 통과
  - `ConstitutiveModelsApplication` Python 바인딩 한계: `MooneyRivlinModel`, `IsochoricMooneyRivlinModel`, `YeohModel`은 C++ 헤더(`custom_models/elasticity_models/`)에는 존재하나 `add_custom_constitutive_laws_to_python.cpp`에 바인딩되어 있지 않음(`hasattr` False)
  - 바인딩된 모델(`LargeStrain3DLaw` + `NeoHookeanModel` / `IncompressibleNeoHookeanModel` / `OgdenModel` / `SaintVenantKirchhoffModel`)은 `TotalLagrangianElement3D4N`과 `UpdatedLagrangianElement3D4N` 모두에서 `Constitutive3DLaw::CalculateDomainVariables` (`constitutive_3D_law.cpp:724`)가 `rDomainGeometry.Volume()`을 호출할 때 `QuadraturePointGeometry`가 `Geometry<Node>::Volume()`을 오버라이드하지 않아 `RuntimeError: Calling base class 'Volume' method instead of derived class one`로 실패
  - 대안 경로 검증 — `ConstitutiveLawsApplication.HyperElastic3DLaw` (압축성 Neo-Hookean: $\mathbf{S} = \lambda \ln(J)\mathbf{C}^{-1} + \mu(\mathbf{I}-\mathbf{C}^{-1})$, `YOUNG_MODULUS=3.0`, `POISSON_RATIO=0.3`):
    - `UpdatedLagrangianElement3D4N` 1셀(p=1, $\lambda_1=1.2$): $\sigma_{11}$ 최대오차 `6.661e-16`, $S_{11}$ 오차 `5.551e-16`, 횡응력 $|\sigma_{22}|,|\sigma_{33}|$ `8.327e-16`, 횡연신 $\lambda_t$ 오차 `0.000e+00` (허용 `1e-11`, 목표 `1e-8`)
    - `UpdatedLagrangianElement3D4N` 패치(p=2, `2x2x2` 셀, $\lambda_1=1.2$): $\sigma_{11}$ 오차 `3.331e-15`, $S_{11}$ 오차 `2.220e-15`, 횡응력 `3.886e-15`, $\lambda_t$ 오차 `1.110e-16`
    - 압축~인장 곡선 검증($\lambda_1 \in \{0.85, 1.05, 1.2, 1.35, 1.5\}$): $\sigma_{11}$ 오차 각각 `8.882e-16`, `3.608e-16`, `6.661e-16`, `8.882e-16`, `2.220e-16`
  - 주의(결함 관측): `TotalLagrangianElement3D4N` + `HyperElastic3DLaw` 조합은 `CalculateOnIntegrationPoints` 경로(`total_lagrangian.cpp:259-260`)에서 `QuadraturePointGeometry`의 참조 형상 야코비안 처리 문제로 간헐적 `DETJ0: -0.5` / `NaN`이 발생함(동일 조건에서 `UpdatedLagrangianElement3D4N`은 안정 동작). 또한 `MoveMeshFlag=True` 및 `mp.SetBufferSize(2)`와 `DisplacementCriteria` 사용이 필수임(`ResidualCriteria`는 초기 잔차 0일 때 1회차에서 조기 수렴)
- 환경: Python 3.12.16, Kratos 10.4.3 (`E:\kratos-build\install`), 2026-11-14
- 결론과 영향: IGA 적분점 기하 위 비선형 초탄성 해석은 `ConstitutiveModelsApplication` 대신 `ConstitutiveLawsApplication.HyperElastic3DLaw` + `UpdatedLagrangianElement3D4N` 경로를 사용한다. Mooney-Rivlin/Ogden 등 다항 초탄성 모델이 필요하면 `ConstitutiveLawsApplication` 확장 또는 C++ `QuadraturePointGeometry::Volume()` 보완이 필요하다.
- 재현: `D:\mamba\envs\whtiga\python.exe -m pytest WHT_IGA/tests/kratos_spikes/test_s19_constitutive_models.py -v -s`

## 정정 (2026-11-14, 통합 담당 — REVIEW_P0_P1 §1 #8)

본문 "주의(결함 관측)"의 TL 간헐 `DETJ0: -0.5` / NaN은 TL이나 적분점 기하의 결함이 아니다. 원인은 **NurbsVolume 수명**이다.

- 원인 경로: `_solve_uniaxial`이 반환되면 `NurbsVolumeGeometry`의 마지막 Python 참조가 사라진다. QP 기하는 parent 포인터만 갖고 있으므로 해제된 메모리를 가리키게 된다.
  - TL의 `CalculateDerivativesOnReferenceConfiguration`은 `GeometryUtils::JacobianOnInitialConfiguration`을 거쳐 `QuadraturePointGeometry::ShapeFunctionsLocalGradients(point)`를 호출하고, 이 함수는 parent에 위임한다 (`base_solid_element.cpp:1733-1740`, `quadrature_point_geometry.h:509-518`). 그래서 TL은 해제된 parent를 읽는다.
  - UL은 QP에 저장된 기울기만 쓰므로 영향이 없다.
- 실측 (같은 프로세스에서 모델 반복 생성, p=1 1셀과 p=2 2×2×2):
  - 참조를 유지하지 않으면 TL 12회 중 6회 NaN, UL은 0회.
  - 참조를 유지하면 TL 0/12.
- 수정: `wht_iga/kratos_backend/geometry.py`의 `make_nurbs_volume`이 `model_part.AddGeometry(volume)`를 호출해 모델 파트가 volume을 소유하게 했다. 이후 수동 참조 없이 TL 0/12 NaN을 확인했다.
- 시험: `test_cl_hyperelastic_uniaxial_matches_analytic`에 TL을 추가했다(반복 4회 × p=1, 2, 매 회 `gc.collect()`). 결과 오차 < 1e-11.
- 결론 변경: 초탄성 경로에서 TL도 사용할 수 있다. ADR-001 failover 7(volume 수명)은 빌더 규약이 아니라 공유 모듈에서 처리된다.
- 남은 사항: `MoveMeshFlag=True`가 필수인 이유는 Kratos TL이 F를 현재 절점 좌표(J)와 초기 좌표(J0)로 계산하기 때문이다(`total_lagrangian.cpp` `CalculateKinematicVariables`). IGA에만 해당하는 문제가 아니다. 음성 시험은 S21에 있다.
