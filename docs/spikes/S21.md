# S21 구속식(`LinearMasterSlaveConstraint`, c=0) + 비선형 Newton (`TotalLagrangian`)

- 질문: 구속식(`LinearMasterSlaveConstraint`, $c=0$ 규칙) + 비선형 Newton 전략(`ResidualBasedNewtonRaphsonStrategy`, `TotalLagrangian`)에서 slave 자유도 값 복원 및 수렴이 정상 동작하는가?
- 결과: 예 (단, `MoveMeshFlag=True` 및 `AndCriteria(ResidualCriteria, DisplacementCriteria)` 사용 필수)
- 근거 (`tests/kratos_spikes/test_s21_newton_constraints.py`, 3/3 통과):
  - 무구속 대변형 외팔보 기준 (`TotalLagrangianElement3D4N`, `KirchhoffSaintVenant3DLaw`, $E=100, \nu=0.3$, `3x1x1` p=1): 참조 Python St. Venant-Kirchhoff Newton (5회 반복) 대비 최대 변위 차 `5.107e-15` (`max|u|=0.590720`), 변형 좌표 동기화 오차 `2.082e-16` (허용 `1e-8`).
  - 구속식 포함 대변형 외팔보 (자유 master + 고정 Dirichlet master 혼합, `3x2x1` p=1, `c=0` 규칙): 참조 $T^T K_t T$ Newton (5회 반복) 대비 최대 변위 차 `1.443e-15` (`max|u|=0.321772`), 구속식 복원 오차 `1.388e-17`, 변형 좌표 동기화 오차 `2.151e-16` (허용 `1e-8`).
  - 0이 아닌 Dirichlet master 포함 케이스 (`2x1x1` p=1, `u_dir=(0.12, 0.25, -0.08)`, `c=0` 규칙): 참조 $T^T K_t T$ Newton (5회 반복) 대비 최대 변위 차 `2.116e-16` (`max|u|=0.250000`), 구속식 복원 오차 `6.939e-18`, 변형 좌표 동기화 오차 `1.110e-16` (허용 `1e-8`).
  - **발견된 Kratos 주의사항 2건**:
    1. `ResidualBasedNewtonRaphsonStrategy`의 8번째 인자 `MoveMeshFlag`를 `False`로 두면 `TotalLagrangianElement3D4N`이 현재 위치(`node.X`)에서 $F=I$로 평가해 internal force가 0이 되어 수렴하지 않음 (`MoveMeshFlag=True` 필수).
    2. 외력(Condition) 없이 Dirichlet 변위만 부과된 비선형 문제에서 `ResidualCriteria` 단독 사용 시 첫 반복에서 `Obtained ratio = 0`으로 판정되어 1 iteration 만에 거짓 수렴(`max|u_k-u_ref|=1.646e-02`) 발생. `AndCriteria(ResidualCriteria, DisplacementCriteria)` 사용 시 5회 이차 수렴으로 `2.116e-16` 달성.
- 환경: Python 3.12.16 (`whtiga`), Kratos 10.4.3 소스빌드 (`E:\kratos-build\install`), 2026-11-14
- 결론과 영향: `LinearMasterSlaveConstraint` ($c=0$ 규칙)는 `TotalLagrangian` 비선형 Newton에서도 `1e-15` 정밀도로 동작하며 slave 좌표(`MoveMeshFlag=True`)까지 정확히 복원된다. 비선형 해석 전략 구성 시 `MoveMeshFlag=True`와 `AndCriteria(ResidualCriteria, DisplacementCriteria)`를 표준으로 채택해야 한다.
- 재현: `D:\mamba\envs\whtiga\python.exe -m pytest -s WHT_IGA/tests/kratos_spikes/test_s21_newton_constraints.py`

## 음성 시험 추가 (2026-11-14, 통합 담당 — REVIEW_P0_P1 §1 #8)

주의사항 2건을 시험으로 고정했다. 사례는 0이 아닌 Dirichlet master 사례(`_nonzero_dirichlet_case`)를 그대로 쓴다.

- `test_s21_negative_residual_criteria_alone_false_convergence`: `ResidualCriteria`만 쓰면 Kratos는 `converged=True`를 보고하지만 max|u_k−u_ref| = 1.646e-02이다(본문 수치 재현).
- `test_s21_negative_move_mesh_false`: `MoveMeshFlag=False`이면 좌표가 움직이지 않는다(max|X−X0| = 0). 이때도 Kratos는 `converged=True`를 보고하지만 max|u_k−u_ref| = 1.315e-01이다.
  - 본문의 "수렴하지 않음"은 정확하지 않다. 실제로는 **수렴했다고 보고하면서 틀린 답을 낸다.** 수렴 플래그만으로는 이 오류를 잡을 수 없으므로 빌더가 두 설정을 강제해야 한다.
- 원인: Kratos TL은 F를 현재 절점 좌표로 계산한다. 이 점은 IGA와 무관하다.
