# S25 Explicit penalty 접촉 (표면층 기반 직접 penalty)

- 질문:
  1) `explicit_penalty_contact_process`가 IGA QP 요소 포함 모델에서 초기화되는가?
  2) 표면층(`Triangle3D3` + `LinearMasterSlaveConstraint`) + Python 직접 penalty로
     두 IGA 블록 자유-자유 충돌이 운동량 보존 하에 안정 적분되는가?
- 결과:
  1) **아니오 (S22와 동일 실패)** — `ExecuteInitialize` → `GenerateFaces` on QP geometry
     `RuntimeError` (pair/self 두 구성 모두).
  2) **예 (직접 penalty)** — 자유-자유 1×1×1 p=1 2블록, 초기 간격 0.1, 상부 v=-1:
     200스텝 안정, 총 운동량 편차 `4.4e-16` (게이트 1e-6 대비 여유 9자리),
     최대 침투 `0.006` (간격의 6 %), `k_pen = 2000`, `dt = 0.005`.
- 근거: `tests/kratos_spikes/test_s25_explicit_contact.py` (3/3 통과),
  probe `probe_s25.py` (부호 반전 시행착오 포함 — 하위 블록은 -z, 상위는 +z가 내력쌍).
- 재현: `D:\mamba\envs\whtiga\python.exe -m pytest -s WHT_IGA/tests/kratos_spikes/test_s25_explicit_contact.py`
- 환경: Python 3.12.16 (`whtiga`), Kratos 10.4.3 (`E:\kratos-build\install`), 2026-11-16

## 결론과 영향
- Kratos 고수준 접촉 프로세스(`mesh_tying`, `penalty_contact`,
  `explicit_penalty_contact`)는 모델에 QP 요소가 하나라도 있으면
  `InterfacePreprocessCondition::GenerateFaces`에서 실패한다 (S22 + 본 확인).
- V-EXP-C는 **직접 penalty 경로**로 간다: 표면층 + MPC tie + Python 루프에서
  간격 측정 → 침투량 비례 내력쌍(`POINT_LOAD`) → Kratos explicit 적분.
  운동량은 내력쌍이라 반올림 수준으로 보존된다.
- Alpha 모듈(`wht_iga/dynamics/explicit.py`)에는 접촉 특화 코드를 넣지 않았다 —
  S25 패턴(간격 측정 + penalty 하중 갱신 + Kratos 스텝)이 V-EXP-C 테스트에 직접 있다.
  일반화(마찰 μ, 탐색 반경, 다중 쌍)는 Phase 6 본 구현 범위.
