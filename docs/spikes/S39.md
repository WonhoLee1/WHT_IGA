# S39 Kratos hybrid 요소 조사: Q1P0는 있으나 셀 QP 기하에서 발산 (2차 정정 2026-11-19)

## 질문
Kratos에 Abaqus hybrid 요소(C3D8H급 U-P)에 해당하는 것이 있는가? 우리 QP 경로에서 쓸 수 있는가?

## 결과: 요소는 있으나 지금은 쓸 수 없음. 원인은 기하 구조가 아니라 요소·법칙 동작(미진단).
- 재고 (전부 C++ 등록됨, Python 이름으로 생성 가능):
  `TotalLagrangianQ1P0MixedElement3D{4,8,10}N` 등, 2D 변형 (유한변형 Q1/P0, C3D8H 대응),
  `SmallDisplacementMixedVolumetricStrainElement*`, `SmallDisplacementMixedStrainElement*`,
  `SmallDisplacementBbarElement*`, OSS 변형들.

## 정정 이력
1. 초판 "Q1P0가 QP 기하를 받아들이지 않음" → 철회.
   `TotalLagrangianQ1P0MixedElement::Create(NewId, pGeom, pProps)`
   (`total_lagrangian_q1p0_mixed_element.cpp:61-67`)는 넘겨받은 기하를 그대로 쓴다.
2. 1차 정정 "요소당 적분점 1개라 P0 응축이 퇴화" → **철회 (틀림)**.
   `attach_cell_elements`는 셀의 Gauss 점 전부를 QP 기하 하나에 담는다(K2).
   실측: 요소당 적분점 p=1 → 8, p=2 → 27 (`GetGeometry().IntegrationPointsNumber()`).
   따라서 Q1P0의 요소 상수 압력 = 셀 상수 압력 = Coreform U/P0와 같은 구조다.
   "셀 기하 생성 C++"도 필요 없다(이미 Python에서 다점 셀 기하가 만들어짐).

- Kratos 소스 트리에 Q1P0를 쓰는 시험·json이 없다(`*.py`, `*.json` grep 0건). 상류에서도 검증되지 않은 요소로 본다.
- 함정: NaN 변위에서 `DisplacementCriteria`가 수렴으로 판정한다. 수렴 판정 뒤 값의 유한성도 확인할 것.

## 결론과 영향
- QP 경로에서 혼합·B-bar·Q1P0 요소 사용 금지 유지. `kratos_backend/elements.check_qp_element_name`
  가드가 검증된 계열(SmallDisplacement / TotalLagrangian / UpdatedLagrangian)만 허용한다
  (`tests/unit/test_qp_element_guard.py`).
- 잠김 해소 1순위: Numba 셀 단위 평균 팽창 F̄/P0 (`analyses/fbar.py`). Coreform U/P0와 같은 구조.
- Q1P0 원인 진단(압력 갱신 `FinalizeNonLinearIteration`, 법칙의 체적 성분 이중 계산 여부)은 보류.
  성공하면 Kratos 전략과 바로 합쳐지는 경로라 가치는 있으나, 상류 미검증이라 성공 여부가 불확실하다.
- C++ 신규 요소는 Numba F̄로 정식화를 검증한 뒤, Kratos 전략과의 통합이나 속도가 필요할 때 결정한다.
