# S29 Kratos penalty mortar 접촉을 표면층에 직접 연결 (IGA 블록)

## 질문
S22·S25에서 실패한 Kratos 접촉 프로세스를 우회해 IGA 모델에 쓸 수 있을까요? 계획서 §5.9.4의 "직접 접촉 조건 생성" 경로입니다.

## 결과: 무마찰 단방향 접촉 성공. 마찰은 Kratos 10.4 한계로 안 됨.
- 됨: 초기화, 압축, **분리(인장 0)**, 초기 간격 열림/닫힘, 누르기–풀기–당기기 이력.
- 안 됨: 마찰. Kratos 자체 결함이며, 표준 FE 공식 테스트에서도 Coulomb이 나오지 않습니다(아래 "마찰").
- 재사용 도우미: `wht_iga/analyses/kratos_contact.py` (`add_contact_variables`, `add_tied_quad_layer`, `SurfaceLayerContact`).

### 초기화 우회 2건 (처음 S29)
1. `PenaltyContactProcess`의 `_interface_preprocess`를 하위 클래스에서 빈 함수로 바꿉니다.
   - 실패 원인이던 `GenerateInterfacePart` → `GenerateFaces`를 건너뜁니다.
   - 표면층(꼭짓점을 제어점에 1:1로 묶은 면 조건)이 그대로 접촉면이 됩니다.
2. `ExecuteInitialize` 동안만 `ProcessInfo[IS_RESTARTED] = 1`로 둡니다.
   - 요소 면이 필요한 `NormalCheckProcess`를 건너뜁니다. 표면층 법선은 직접 바깥쪽으로 만듭니다.
   - 끝나면 0으로 되돌립니다. 1로 두면 요소가 구성법칙을 초기화하지 않습니다.

### 분리 실패의 원인 (차등 디버깅)
1. **Kratos 공식 테스트는 우리 빌드에서 맞습니다.** `penalty_frictionless_contact_test_3D/3D_contact_simplest_patch_matching_test`를 scratch로 복사해 `StructuralMechanicsAnalysis`로 실행했습니다.
   - 압축(위 −0.1): 경계면 u_z = −0.04999 / −0.05000. JSON 검사 통과.
   - 당김 변형(위 +0.1): slave `ACTIVE = False`, `WEIGHTED_GAP` = 0.025(= 0.1 × 절점면적 0.25), 아래 블록 u_z = −4.5e-6(테스트 허용오차 1e-4 수준의 잔차).
2. **공식 경로가 S29 설정보다 더 하는 일** (`contact_structural_mechanics_static_solver.py`, `auxiliary_methods_solvers.py`, `contact_convergence_criteria_factory.py`, 구조 solver 기본값)
   - `move_mesh_flag = true` (구조 solver 기본값). S29는 false였습니다.
   - 판정: `MortarAndConvergenceCriteria(DisplacementResidualContactCriteria, PenaltyFrictionlessMortarConvergenceCriteria)`, `SetActualizeRHSFlag(True)`.
   - 전략 `ResidualBasedNewtonRaphsonContactStrategy`(Predict에서 가중 간격 계산·접촉 절점 좌표 이동), 빌더 `ContactResidualBasedBlockBuilderAndSolver`(LM 자유도용, penalty에는 무관).
   - `computing_model_part.Set(INTERACTION, True)`: 매 반복 활성 집합 갱신(없으면 1회째 반복만).
   - 절점 변수 `NORMAL`, `NODAL_H`, `WEIGHTED_GAP`. `clear_storage`·`reform_dofs_at_each_step = true`. 비선형 반복 훅은 판정 객체가 담당합니다(`PreCriteria`/`PostCriteria`).
3. **같은 수동 설정을 표준 FE(hexa8, 공식 경계면 생성, 표면층 없음)에 적용해도 똑같이 실패**했습니다(mesh 고정: 힘 0.867, 당겨도 −0.867, 활성 1/4, `WEIGHTED_GAP` ≈ 1e-17). 따라서 IGA·표면층 문제가 아닙니다.
4. 원인을 하나씩 분리했습니다(E = 1000, ν = 0, penalty 1e6, 위 ∓0.01, 기준 4.990).

- `SmallDisplacementElement`(QP 형상)는 기준 형상으로 B를 계산하므로 mesh 이동이 강성을 바꾸지 않습니다. FE hexa8과 IGA 반력이 4.990020으로 같습니다.

### 레시피 (`kratos_contact.SurfaceLayerContact`)
- 우회 2건 + `MoveMeshFlag = True` + `MortarAndConvergenceCriteria(DisplacementContactCriteria, PenaltyFrictionlessMortarConvergenceCriteria)` + 사각형 표면층 + `INTERACTION`·접촉 전략·접촉 빌더(공식 구성).
- 단계 순서: `CloneTimeStep` → 하중/변위 지정 → `process.ExecuteInitializeSolutionStep`(탐색) → 전략 `InitializeSolutionStep`·`Predict`·`SolveSolutionStep`·`FinalizeSolutionStep` → `process.ExecuteFinalizeSolutionStep`.
- 함정
  - 수렴 여부는 `SolveSolutionStep` 반환값으로 봅니다. `FinalizeSolutionStep` 뒤 `IsConverged()`는 이미 비운 행렬로 판정을 다시 돌려 access violation이 납니다.
  - Newton 기반 생성자가 판정 echo를 1로 바꾸고 접촉 전략이 매 단계 되돌립니다. 도우미가 `InitializeSolutionStep` 뒤 다시 0으로 둡니다.
- penalty 의미: 조건마다 penalty × (그 조건의 가중 간격)을 다시 적분합니다. 균일 간격이면 사각형 한 쌍(면적 A_e)의 스프링은 penalty·A_e²/4, 경계면은 그 합입니다. 단위면적당 c·E/h를 원하면 penalty ≈ 4cE/(h·A_e). 삼각형 층은 절점 변위가 균일하지 않아(측정) 이 식(penalty/6)이 맞지 않습니다. S29의 "0.148배"는 그 경우입니다.
- 1:1 묶음은 면이 제어점을 보간할 때만(p = 1) 정확합니다. p ≥ 2는 스플라인 기저로 묶어야 하며 도우미에는 없습니다.

### 마찰 (stretch goal): 안 됨
- 시험: 같은 IGA 사각형 층, μ = 0.3, 위 −0.01로 누른 뒤(N = 4.990, μN = 1.497) 위면을 x로 0.5e-3 → 8e-3 이동.
  - 접선 반력 R_x = 1.1e-5 … 2.9e-3. 경계면 상대 미끄럼 ≈ 이동량. Kratos 판정은 내내 stick.
  - μ = 0(절점 μ 미설정)과 μ = 0.3의 R_x가 7자리까지 같습니다. 마찰항이 사실상 0입니다.
- 설정 함정: `ALMFastInit`는 μ를 **표면층 조건의 Properties**에서 읽어 절점 `FRICTION_COEFFICIENT`로 옮깁니다. 공정의 `friction_coefficients`(쌍 Properties)만으로는 절점 μ = 0입니다. 고쳐도 결과는 같았습니다.
- 표준 FE에서도 같습니다. Kratos `penalty_frictional_contact_test_2D/hyper_simple_stick`(μ = 1)을 복사해 실행하면, 접선 이동 구간에서 \|R_x/R_y\| = 0.0005–0.03이고, 위 블록 경계면 절점이 아래보다 6e-3–5e-2 더 움직입니다(미끄럼). 이 테스트는 변위 JSON 회귀만 검사합니다.
- 원인(소스): `penalty_frictional_mortar_contact_condition.cpp`의 잔차에서 접선 성분이 M, D가 아니라 단계 사이 mortar 연산자 **변화량**(M_old − M, D_old − D)에 곱해집니다(예: 3D4N slip 분기 `crhs1 = MOperatorold(0,0) − MOperator(0,0)`, stick 분기 `crhs34`). 그래서 마찰력이 μ·p_n·(미끄럼 증분/요소 크기) 수준으로 작습니다.
- 마찰이 필요하면(V08·E05) 지금은 Python 접촉(Track 3 SSN 일반화, `analyses/contact.py` 계열)이 대안입니다.

## 결론과 영향
- Kratos penalty mortar 접촉은 IGA 블록의 표면층에서 **단방향 무마찰 접촉으로 쓸 수 있습니다.** S29의 "양방향"은 mesh를 고정한 설정 탓이었고, IGA·우회와는 무관했습니다.
- 무마찰 분리가 필요한 경우는 `SurfaceLayerContact`로 갈 수 있습니다. 마찰은 Kratos 10.4 C++ 수정 없이는 안 됩니다.
- 남은 범위: p ≥ 2 면의 기저 묶음, 곡면·비정합 층, TL/UL 대변형 요소와의 조합은 확인하지 않았습니다.
